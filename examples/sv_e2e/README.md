# sv_e2e — Blinky end-to-end example

Minimum reproducible example for the matched SW + HW surface
generated by the `device-driver` SV target.

## Files

* `blinky.ddsl` — single DDSL source. Declares one device with three
  registers: `Ctrl` (RW), `Status` (HW-writable tick + W1C overflow),
  `Period` (RW). Opts into APB3, two SVA assertion classes, and the
  UVM RAL package.
* `tb_blinky.sv` — Verilator co-simulation testbench. Drives the
  regblock via its native CPUIF, simulates user RTL pulsing
  `status_tick_we` and `status_overflow_hwset`, and validates the
  field-level round-trip from both sides.
* `Makefile` — wires it together. `make` generates the SV artifacts,
  compiles the testbench with Verilator, and runs the simulation.

## Run it

```bash
$ cd examples/sv_e2e
$ make
```

If verilator is on `PATH` and the workspace builds, the testbench
prints `[tb_blinky] PASS` and exits 0.

## Generated artifacts

`make generate` writes to `generated/`:

```
generated/
├── blinky.sv                  # package + regs module
├── blinky_apb3.sv             # APB3 wrapper
├── blinky_sva.sv              # SVA checker module
├── blinky_sva_bind.svh        # bind snippet
├── blinky_ral_pkg.sv          # UVM register model
└── blinky_ral_smoke_seq.sv    # UVM smoke sequence
```

Add `sv-bus: native` (or `axi4lite`, `ahblite`) to `blinky.ddsl` for
the corresponding wrappers.

Drop these into your chip's verification + RTL build. The APB3
wrapper expects `psel`/`penable`/`pwrite`/`paddr`/`pwdata`/`prdata`/
`pready`/`pslverr` — wire those to your APB interconnect. The
`hwif_in`/`hwif_out` structs feed your user RTL per
`SV_HWIF_CONTRACT.md`.

## The Rust side

The same DDSL source is consumed by the Rust HAL backend. From any
crate depending on `device-driver`:

```rust
use device_driver_macros::create_device;

create_device!(
    device_name: Blinky,
    manifest: "examples/sv_e2e/blinky.ddsl",
);
```

Now `Blinky::new(interface)` gives you typed `ctrl().enable().write(true)`
accessors that target the same address+bit layout as the generated SV.

## What this validates

* Same DDSL source → both Rust HAL and SV regblock; the addresses,
  field positions, and reset values match by construction.
* The SV regblock under Verilator behaves correctly for the canonical
  cascade arms (HW write, HW set strobe, SW W1C).
* The HW-side `hwif_in` / `hwif_out` contract documented in
  `SV_HWIF_CONTRACT.md` is reproducible from a doc-sized example
  rather than only inside the project test suite.
